# 新しいページの公開検知（お知らせの下書き自動作成）

ホームページに新しいページを公開すると、「最新のお知らせ」の**下書き（非公開）**が執行部ポータルに自動でできます。
内容を確認して「公開する」を押すと、トップページと /news/ に表示されます。

## 何が「新しいページ」として検知されるか

本番サイトのサイトマップ（/sitemap-index.xml）に、これまで無かったURLが増えたときだけです。

| 変更の種類 | 検知されるか |
|---|---|
| 新しいページの公開（例：/stamp-rally/） | される（下書き） |
| 準備中（noindex）だったページの公開（例：フォームURLの設定で /voice-post/ が公開された） | される（下書き） |
| 活動報告の記事の公開（/activities/〜） | される（下書き、カテゴリー「活動報告」） |
| 既存ページの文言・誤字・デザイン・SEO・内部コードの変更 | されない（サイトマップが変わらないため） |
| トップページ・お知らせ記事（/news/〜）・執行部ポータル | されない（対象外） |
| 執行部ポータルで登録するイベント | 既存のイベント連携（「最新のお知らせにも掲載する」）を使う |

## 流れ

1. mainへpushすると、GitHub Actions（`.github/workflows/detect-new-pages.yml`）が起動する
2. 本番の `/build-version.json` が、pushしたコミットになるまで待つ（最大20分）
   ＝Cloudflare Pagesへのデプロイ完了を確認する。push成功だけでは判定しない
3. 本番の `/api/admin/detect-new-pages` を呼ぶ（秘密キーで認証）
4. サイトマップに新しく増えたページごとに、お知らせの下書きを作る
   - タイトル：「（ページのタイトル）」のページを公開しました
   - 概要：ページの説明文（meta description）
   - 掲載日：公開を確認した日（日本時間）
   - リンク先：そのページ
5. 執行部ポータル（/staff/news/）に【確認待ち】と表示される。確認して公開する

GitHub Actionsのログ（Actionsタブ → Detect new pages）にも、作成した下書きと要確認のページが表示されます。

## 重複・誤掲載の防止

- 1ページにつきお知らせは1件だけ（識別子 `page:<パス>`）。Actionsを再実行しても二重にできない
- 既存のお知らせ（執行部ポータル・記事ファイル）がすでにそのページへリンクしていれば、下書きを作らず「要確認」にする
- 下書きは必ず非公開。執行部が公開するまで一般の画面には出ない
- デプロイが完了しない・失敗した場合は何もしない
- サイトマップや記事一覧を読めない場合は何もしない（次回に再確認）
- 一度に11ページ以上増えた場合（URLの整理など）は、下書きを作らず「要確認」として毎回報告する
  - 確認し終えたら、Actionsタブ → Detect new pages → Run workflow で「記録するだけ」にチェックして実行すると解消する
- このワークフローはコミットもデプロイもしない（D1に書くだけ）ため、自動処理が連鎖することはない
- 初回は、今あるページを記録するだけでお知らせは作らない

## 本番導入の手順（未実施）

1. 秘密キーを1つ作る（推測できない長いランダムな文字列）
2. Cloudflare Pages → nobeoka-ugokasu → 設定 → 環境変数（Production）に `NEWS_DETECT_SECRET` を暗号化して登録
3. GitHub → Settings → Secrets and variables → Actions に、同じ値で `NEWS_DETECT_SECRET` を登録
4. コミットしてmainへpush（このときのActionsが初回となり、既存ページを記録するだけで終わる）
5. Actionsのログで「状態: baseline」を確認する

秘密キーが未設定の間は、ワークフローは何もせずに終わります（エンドポイントも誰にも実行させません）。

同じ秘密キーを、サイトの定期チェック（docs/site-monitoring.md）でも使います。

## テスト

- `npm run test:page-announcements`（D1はNodeのSQLiteで再現。Cloudflareへはアクセスしない）
- ローカルのテスト環境：`npx wrangler pages dev dist --d1 STAFF_DB --binding NEWS_DETECT_SECRET=<テスト用の値> --persist-to <一時フォルダ>`
  （ローカルのD1は本番とは別。--persist-to には一時フォルダを指定する）
