# イベントの管理（/staff/events/）

執行部ポータルからイベントを登録・管理します。「一般公開」にしたイベントだけが、
トップページ「今後のイベント」（直近3件）とイベント一覧 <https://nobeoka-ugokasu.pages.dev/events/> に表示されます。

> **意見交換会は別管理です。** 意見交換会は執行部ポータルの「意見交換会」（/staff/dialogue/）で登録してください。
> イベント管理のカテゴリー「意見交換」は、意見交換会以外の交流・懇談の催しのためのものです（データも別のテーブルです）。

## 画面

| URL | 内容 |
|---|---|
| `/staff/events/` | 一覧（今後のイベントを上、終了・中止・開催日を過ぎたものを下。PCは表、スマートフォンはカード）・ステータス変更・編集・削除 |
| `/staff/events/new/` | 新規登録 |
| `/staff/events/:id/edit/` | 編集 |

## 入力項目

| 区分 | 項目 | 公開ページへの表示 |
|---|---|---|
| 基本情報 | イベント名・開催日・開始／終了時間・会場・住所・概要 | 一般公開のとき表示 |
| 基本情報 | カテゴリー（後援会活動／地域イベント／意見交換／ボランティア／街頭活動／会議／その他） | 一般公開のとき日本語で表示 |
| 基本情報 | ステータス（企画中／準備中／受付中／開催予定／終了／中止） | 一般公開のとき日本語で表示 |
| 基本情報 | 公開範囲（一般公開／執行部のみ）。**初期値は「執行部のみ」** | — |
| 参加関係 | 定員・ボランティア募集目標人数・現在のボランティア人数（0以上の整数） | 表示しない |
| 内部管理 | 担当者・必要物品・内部メモ | **表示しない** |

ボランティアの氏名・連絡先などの個人情報は登録しません（人数のみ）。将来ボランティア申込フォームと連携する場合は、
人数（`volunteer_count`）をフォームの集計から更新する形で拡張できます。

## 公開ページでの表示

- `/events/`：今後のイベント（開催日の近い順。中止は「中止」と表示）と、「これまでのイベント」（終了・開催日を過ぎたもの。新しい順に20件まで）。
- トップページ「今後のイベント」：直近3件（中止は除く）。該当するイベントが無い場合は、セクションごと表示しません。
- 受付中・開催予定・中止の今後のイベントは、検索エンジン向けの構造化データ（schema.org Event）も出力します。

## 「最新のお知らせ」との連携

- 「最新のお知らせにも掲載する」にチェックした一般公開イベントだけ、カテゴリー「イベント」で「最新のお知らせ」に1件掲載します。
  タイトルはイベント名、概要は「開催日 時間、会場：○○。概要」、リンク先は `/events/#event-<id>` です（担当者・内部メモ等は含めません）。
- 紐づけは `news_items.source_key = "event:<イベントID>"` で行います（一意なので、何度保存してもお知らせは1件のままです）。
- イベントを編集すると、お知らせのタイトル・概要も更新されます（掲載日は最初に掲載した日のまま）。お知らせ管理で文言を直しても、イベントを保存すると上書きされます。
- チェックを外す／「執行部のみ」にする／イベントを削除すると、お知らせは**非公開**になります（削除はしません。お知らせ管理から確認できます）。
- 「執行部のみ」のイベントは、お知らせに掲載できません。

## 削除

削除は「論理削除」（`deleted_at`）です。一覧・公開ページからは消えますが、D1には行が残ります。

## 仕組み（開発者向け）

- 保存先：Cloudflare D1（binding `STAFF_DB`）の `events`。操作ログは `staff_audit_log`（`event.create`・`event.update`・`event.status`・`event.visibility`・`event.delete`、お知らせ連携は `news.sync`）。担当者・内部メモなどの内容はログに残さず、変更した項目名だけを記録します。
- テーブルは最初のアクセス時に作成されます。同じ定義を `migrations/0004_events.sql` に置いています（`server/events.ts` の `EVENTS_SCHEMA_SQL` から生成。明示的に適用する場合は `npm run d1:migrate`）。
- 公開／内部の判定：公開ページ用の読み出し（`listPublicEvents`）は `visibility = 'public'` かつ未削除の行の、公開してよい列だけを SELECT します。内部管理用の列は公開ページ・公開用の処理に一切渡りません（テストで確認）。
- 公開ページ：`src/pages/events/index.astro`・`src/pages/index.astro` の静的HTMLを、`functions/events/index.ts`・`functions/index.ts` が配信時に差し替えます（共通処理 `server/publicRewrite.ts`、HTMLは `src/utils/eventCards.ts`）。D1に障害がある場合は静的HTML（予定なしの表示）のまま表示されます。
- 管理API：`/staff/api/events`（GET・POST）、`/staff/api/events/:id`（GET・PUT・PATCH・DELETE）。ログイン確認・Origin・CSRFトークンはミドルウェア、入力値は `server/events.ts` で検証します。
- テスト：`npm run test:events`
