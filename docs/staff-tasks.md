# タスクの管理（/staff/tasks/）

執行部内のやること・担当者・期限・優先度・進捗を管理します。**執行部ポータルの中だけ**で使い、公開ページには一切表示しません。

## 画面

| URL | 内容 |
|---|---|
| `/staff/tasks/` | 一覧（PCは表、スマートフォンはカード）。絞り込み（未完了／期限切れ／すべて）、完了・未完了に戻す、優先度・進捗の変更、編集、削除 |
| `/staff/tasks/new/` | 新規登録 |
| `/staff/tasks/:id/edit/` | 編集 |

## 入力項目

| 項目 | 内容 |
|---|---|
| タスク名 | 必須・100文字まで |
| 担当者 | 任意・自由記入（例：盛武、福富、事務局、広報担当）・50文字まで |
| 期限 | 任意（日付） |
| 優先度 | 高・中・低（初期値は中）。一覧では「高」を赤で強調 |
| 進捗 | 0〜100%（画面では10%刻みで選択。保存値は0〜100の整数） |
| メモ | 任意・2000文字まで |
| 完了／未完了 | 完了にすると進捗100%・完了日時・完了した人を記録 |

## 完了と進捗

- 完了にすると、進捗は必ず100%になり、完了日時と完了操作をした人（ログイン中のアカウント）を記録します。
- 未完了に戻すと、**完了にする直前の進捗**に戻ります（記録が無い場合・直前が100%だった場合は90%）。
- 未完了のまま進捗を100%にはできません（100%にしたい場合は「完了」にします）。一覧で進捗を100%に変えると完了になり、完了済みのタスクの進捗を下げると未完了に戻ります。

## 一覧の表示

- 期限の状態は、色だけでなく文字でも表示します：「期限切れ」「今日まで」「近日中」（3日以内）、「期限なし」。
- 並び順：未完了（期限切れ → 期限が近い → 優先度「高」→ 期限あり → 期限なし）→ 完了済み（「すべて」を選んだときに下へ表示。完了の新しい順）。

## 仕組み（開発者向け）

- 保存先：Cloudflare D1（binding `STAFF_DB`）の `tasks`。削除は論理削除（`deleted_at`）。
- 操作ログ：`staff_audit_log` に `task.create`・`task.update`・`task.complete`・`task.reopen`・`task.priority`・`task.progress`・`task.delete` を記録します。担当者・メモの内容は残さず、変更した項目名だけを記録します。
- テーブルは最初のアクセス時に作成されます。同じ定義を `migrations/0005_tasks.sql` に置いています（`server/tasks.ts` の `TASKS_SCHEMA_SQL` から生成。明示的に適用する場合は `npm run d1:migrate`）。
- 管理API：`/staff/api/tasks`（GET・POST）、`/staff/api/tasks/:id`（GET・PUT・PATCH・DELETE）。ログイン確認・Origin・CSRFトークンはミドルウェア、入力値は `server/tasks.ts` で検証します。公開ページ用の処理（`functions/index.ts` など）は `tasks` を読みません（テストで確認）。
- 並び順・期限の状態：`src/utils/taskOrder.ts`。
- 担当者を将来メンバー管理と連動させる場合：`tasks` に `assignee_member_id` 列を追加し、`src/components/staff/TaskForm.astro` の担当者の入力欄を選択式に、`server/tasks.ts` の `validateTaskInput` の担当者の検証を選択肢のチェックに差し替えます（既存の自由記入の値はそのまま表示できます）。
- テスト：`npm run test:tasks`
